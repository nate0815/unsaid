# 正規式裡的 Unicode 跳脫被寫成真字元，播放器打包報「Unterminated regular expression」

**現象**
- 播放器打包（Vite／rolldown）報 `Unterminated regular expression`，指向 `src/core/project.ts` 的 `jsonForScript`。
- tsc 型別檢查完全沒報錯，編輯器裡看那一行也像是正常的 `/ /g` —— 中間的字元是看不見的。
- 同一批檔案裡，測試字串中的零寬空白、組合附加符號也變成了看不見的真字元（測試照樣通過，但沒人看得出那裡有字）。

**原因**
- AI 寫檔時送出的文字裡，「反斜線＋u＋四位十六進位」這種跳脫序列，在寫進檔案之前就被轉成了它代表的那個字元。
- 被轉成的是 U+2028（行分隔符）。它在 JavaScript 原始碼裡算**換行**，正規式字面值於是在中間斷掉。

**解法**
- 原始碼裡需要特殊字元時，一律用 `String.fromCharCode(0x2028)`／`String.fromCodePoint(0x200b)` 產生，不寫跳脫序列（`core/project.ts` 的 `LINE_SEP`、`tests/width.test.ts` 的 `cp()`）。
- 寫完檔掃一次看不見的字元：用 Python 走過 `src/ tests/ tools/`，列出 Unicode 類別為 Zl／Zp／Cf／Mn／Cc 的字元（⚠️ 表情符號自帶的 U+FE0F 是正常的）。
