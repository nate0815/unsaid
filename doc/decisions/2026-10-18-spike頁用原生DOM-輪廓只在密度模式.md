# spike 頁用原生 DOM；輪廓只在密度模式生效

**選了什麼**
- M1 試作頁（`src/spike/`）用原生 DOM 做控制面板，不引入 React。畫面本身走正式的 `core` ＋ `player`，
  所以 spike 裡看到的就是之後播放器畫出來的樣子。
- 輪廓（`/ \ | -` 描邊）只在密度模式套用。

**沒選什麼、為什麼不選**
- **spike 先用 React**：M3 編輯器才需要 React ＋ React Flow；spike 若 H1 不過就停在這裡，先拉相依是白付成本。
  原生 DOM 的控制面板約 200 行，M3 時整頁換掉。
- **輪廓兩種模式都套**：描邊字元會插進那句話中間，訊息填充模式就讀不出句子了 —— 那是它存在的理由。
  DESIGN「圖片轉字元」只說輪廓「可選」，沒有指定模式，這不算偏離規格。

**如果錯了會怎樣**
- Chiao 若覺得訊息填充模式也需要輪廓，可以改成「描邊格不消耗句子的字」，但要先確認可讀性。
