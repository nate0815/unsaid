# 存檔格式：字元格存成「每列一個字串」＋ base64

**選了什麼**
- 專案存檔（也是匯出 HTML 內嵌的資料）帶 `format: 'unsaid'`、`version: 1`、`cellAspect`。
- 字元格每列存成一個字串：全形字只寫一次，佔的兩格由 core 的字寬表推回來；空格 = 沒字。
- 明顯程度存成每格一個位元組（0～255）、顏色每格三個位元組，各自 base64。全部不透明時不存 alpha，單色時不存顏色。
- 執行期格式（core 的 `Grid`／`Clip`）與存檔格式分開，只經 `encodeProject`／`decodeProject` 轉換。

**沒選什麼、為什麼不選**
- **直接 `JSON.stringify` 執行期的 `Cell[]`**：每格一個物件，80×35 的畫面就是 2800 個 `{"ch":…,"w":…,"a":…}`，大十倍以上。
- **連全形字的右半格也寫進字串（例如用佔位字元）**：字串就不是人讀得懂的那句話了；手改專案 JSON 時也容易弄壞成對關係。
- **一開始就 gzip**：見 DEVLOG 待決 —— 實測可縮到約 1/9，但播放器要改成非同步啟動，等 Chiao 看過數字再決定。

**如果錯了會怎樣**
- 字寬表若改了（例如某個符號從 1 格改成 2 格），舊檔的字串會被解讀成不同的位置。所以字寬表的變動要當成格式變動：加 `FORMAT_VERSION` 並寫遷移（TECH「不變式」）。
- 明顯程度只有 256 階，和預覽的浮點數最多差 1/255 —— 預覽本身就是匯出檔，所以兩邊看到的一樣。
