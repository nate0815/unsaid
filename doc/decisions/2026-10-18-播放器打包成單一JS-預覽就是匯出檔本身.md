# 播放器打包成單一 JS 內嵌；預覽就是匯出檔本身

**選了什麼**
- `src/player/main.ts` 由 `tools/player-bundle.ts` 用 Vite 打包成一支 IIFE（目前 14.8 KB），透過虛擬模組
  `virtual:unsaid-player` 交給編輯器端；匯出時整段塞進 HTML 的 `<script>`。
- 建置與開發時都即時打包；開發時改了播放器的任何檔，虛擬模組就失效重打。
- 編輯器的「預覽」= 把**匯出的 HTML 本身**放進 `<iframe sandbox="allow-scripts">`。
- 每次 `npm test` 都打包一次，檢查大小（≤ 40 KB）、只含 core／player、沒有 `</script`。

**沒選什麼、為什麼不選**
- **預覽直接呼叫播放器模組**：同一份原始碼，但經過不同的打包與資料路徑（不經 JSON 編解碼、不經內嵌）。
  兩邊一旦分岔不會報錯 —— 正是 PLAN「核心判斷」要防的事。
- **先 `npm run build:player` 產生檔案再讓主程式讀**：多一個要記得的步驟，開發時改了播放器還得手動重建，忘了就預覽到舊版。
- **匯出時從網路載入播放器**：違反 DESIGN「匯出」的「不需要網路」。

**如果錯了會怎樣**
- 打包在測試與建置時各跑一次（約 0.1 秒），專案變大後若明顯拖慢，可以改成快取。
